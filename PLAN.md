# Plan: RESILIX ActionOps — crisis-to-action war room rebuild
_Locked via grill — by Claude + Sharan (2026-06-12) · Revised after adversarial review rounds 1–3 (interim) + cross-model Codex round 4 (2026-06-12, 12 findings arbitrated — see PLAN-REVIEW-LOG.md)_

## Goal
Reorient the existing repo (Next.js/TS "LaunchOps" salvage) into **RESILIX ActionOps**: a disruption signal + a supplier CSV produces an **evidence-cited, human-approved action packet** — threat card → exposure mapping → 3/7/14/30-day runway simulation (when inventory data present) → role-specific playbooks → drafted supplier emails + task list + executive one-pager. **The speed claim is defined as Scan-now → packet wall-clock: < 5 minutes in live mode (measured, with live-LLM mode asserted), seconds in replay mode (disclosed as replay in the UI; degraded fallback runs visibly badged).** US-primary persona: mid-market manufacturer (50–499 employees). Portfolio-grade: the demo must never fail in a viewer's hands AND never misrepresent replayed or fallback output as live AI. Total spend ≤ $5 (Gemini, mechanism below), everything else free-tier. On-demand runs only — not continuous production.

## Approach
1. **Identity & spec rewrite** (~0.5d) — README + success criteria restate the ActionOps thesis (US-grounded, June 2026 framing, honest positioning: "the integrated loop at spreadsheet-team prices", never "no one does this"). The "2am packet" line is roadmap-gated on scheduled scans or dropped. Limitations paragraph: episodic usage, stale-CSV risk, replay-mode disclosure. _Only this phase may run before the cross-model (Codex) review; phases ≥2 are hard-gated on it._
2. **Data model at scale** (~2.5d) — extend Drizzle/Postgres schema: `suppliers` (~150-row seeded US dataset), `products`, `routes`+`chokepoints` (new), `inventory`, `orders`, `disruption_events` (persisted — GDELT window ~3 months), `exposure_results`, `action_items`, `supplier_messages`; reuse decision-packet/audit/agent-run tables. **Driver swap (Codex R4-3): replace `drizzle-orm/neon-http` with a transaction-capable driver (`drizzle-orm/node-postgres`) — the plan's local-Postgres primary demands real transactions; in-memory fallback preserved.** **Atomic mutations (R4-1/2): approval = one transaction (`UPDATE … WHERE approval_status='PENDING' RETURNING` + audit append + approval-event mark together); concurrent same-key runs are serialized by an in-process keyed mutex so the LLM pipeline runs at most once per key **within the single-instance, on-demand MVP runtime**, and the DB unique constraint on the key blocks duplicate key rows. Cross-INSTANCE reserve-before-work (DB reservation row / advisory lock) is **post-MVP** (tracked in tasks/todo.md P2.1) — not needed for the single-instance MVP.** **Packet contract versioning (R4-7): `packetVersion` field + `DecisionPacketV2Schema` (ActionOps shape); API/UI/tests migrate before any V2 packet persists — no silent reuse of the LaunchOps 3-options/executionDraft contract.** **Tiered CSV schema:** Tier 1 (required, ~8 cols incl. ISO-3166 country code + enumerated sector) unlocks exposure mapping only; Tier 2 (optional: lane/route, on-hand units, daily use, unit revenue) unlocks route analysis + runway. **Tier-1 rule (one rule, no contradiction): a Tier-1-only upload gets NO simulator section — the packet's data-gaps note says why — and the inventory-buffer factor is dropped from its exposure scoring. `ASSUMED (demo data)` stamps are reserved for the seeded demo path only; user uploads never display seed-derived numbers.** **CSV ingestion is now fully specified (R4-5/6): dedicated upload endpoint; parser = papaparse; size cap (≤2 MB) + row cap (≤2,000); duplicate policy (same name+country → last-write-wins with report line); formula-injection sanitization (strip/escape leading `= + - @` on every cell before storage or display); uploaded supplier/product names are canonicalized to internal IDs at ingest — display names are sanitized, and downstream agents/gatekeeper validate against IDs, never raw uploaded strings (uploads are a second injection channel, same quarantine rules as GDELT text); retention rule stated in UI: local demo only, data purgeable via reset.** Per-row matched/unmatched-with-reason report on every upload; semantic validation (country-code normalization, sector taxonomy, whitespace) — silent zero-match structurally impossible. DB = local PostgreSQL via DATABASE_URL; in-memory fallback preserved. **Fail-closed surface rule (R4-4, narrowed): when `DATABASE_URL` or CSV upload is enabled, approve/mutate routes require a bearer `APPROVAL_TOKEN` and the n8n callback secret becomes mandatory (no `DEMO_UNCONFIGURED` pass-through); pure in-memory demo stays authless and the limitations paragraph says so. Full SSO/per-user auth remains expansion-scope. Corollary (Codex closure caveat): live-AI runs are never exposed authlessly — otherwise the $5 budget is unenforceable by strangers hitting the endpoint.**
3. **Signal layer, replay-first** (~1.5d) — **Live fetchers (MVP): GDELT + NWS only** (live-tested 2026-06-12; NWS needs User-Agent). USGS/NHC fixture-only. Open-Meteo removed (DNS SERVFAIL 2026-06-12). GDELT gets a longer timeout + per-scan response cache (throttles, limit unpublished). Snapshot recorder: every scenario ships dated, real, recorded signal fixtures; **capture date rendered in the UI ("Recorded signals: 2026-06-12")**; replay never labeled live. `verify:live` smoke script gates every showcase: both fetchers + **every live prompt/schema pair (Sentinel, Strategist, Dispatcher) with minimal inputs, shape-diffed against fixtures** — a model upgrade that breaks one schema cannot pass on another's green.
4. **Sentinel + Verifier** (~1.5d) — Sentinel (LLM): classifies signals → Threat Card. **Closed vocabulary with an escape hatch:** zod enums (ISO-3166 codes, fixed chokepoint list, fixed sector taxonomy, fixed event types incl. supplier-financial-distress) **plus an explicit `OTHER_UNMAPPED` value in every enum** — constrained decoding force-fits novel events into valid values rather than failing, so the escape hatch is the real firewall; Atlas treats `OTHER_UNMAPPED` as no-match-with-stated-reason. **Supplier-name extraction (bankruptcy event type) is a dynamic enum: the extracted string is validated against the known suppliers table (exact-or-normalized match, no fuzzy); only the matched supplier ID crosses into Atlas/packet — the raw extracted string never does.** Only Sentinel ever sees raw article text. Evidence URLs validated against the fetched-set allowlist. Verifier is fully deterministic (source count, recency, corroboration, geo plausibility) — **its rationale is templated from its own check outputs ("3 sources, all <48h, 2 independent outlets"), no LLM call** (an LLM paraphrase can misdescribe the one component whose job is trust). Re-verify the Gemini lineup at phase start (ListModels + AI Studio dashboard screenshot for free-tier limits — officially unpublished); **default = GA model alias, previews opt-in via `GEMINI_MODEL`**. **Mode taxonomy split (R4-8): the single `DETERMINISTIC_FALLBACK` value is replaced by `LIVE_AI` / `DETERMINISTIC_RULES` (healthy by-design deterministic components: Verifier, Atlas, Simulator, gatekeeper) / `REPLAY` / `FAILED_TO_FALLBACK` (live AI attempted and failed); packets carry requested-vs-effective mode — the UI "degraded" badge keys off `FAILED_TO_FALLBACK` only, never off healthy deterministic runs.**
5. **Atlas exposure engine, deterministic TS** (~1d) — match event → suppliers/products/routes on the closed vocabulary (country, sector, chokepoint, product dependency, backup availability; inventory buffer only when Tier-2/seeded data exists; validated supplier-ID match for bankruptcy). Unit-tested against hand-computed fixtures. Eval cases include: deliberate-misclassification (bad output fails loudly) AND **off-taxonomy live case (an article outside the enums must land in `OTHER_UNMAPPED`, not get force-fitted to a named chokepoint)**.
6. **Simulator, deterministic TS** (~1d) — 3/7/14/30-day scenarios: runout dates per product, revenue-at-risk over time, mitigation options (expedite/alternate/air-freight) cost-benefit ranked. Unit-tested against hand-computed fixtures. Runs only on Tier-2 or seeded inventory data (per the phase-2 Tier-1 rule).
7. **Strategist + Dispatcher, LLM, gatekept** (~1.5d) — Strategist: role playbooks grounded ONLY in Atlas/Simulator numbers. **Dispatcher receives structured numbers + whitelisted event fields only — never raw article text.** **Drafts capped at the top-5 exposed suppliers — ranked by revenue-at-risk when Tier-2/seeded data exists, else by exposure score — + one reusable template for the tail** (unbounded per-supplier drafting in one call risks truncation → whole-batch zod failure). Gatekeeper extended with enumerated checkable classes (the salvage gatekeeper's set-membership pattern): **every numeral in a draft must appear in structured inputs; URLs must be in the evidence allowlist; entity names must come from the known supplier/product set** — no open-ended "factual substring" claims. **Structured-claims hardening (R4-9, narrowed): Dispatcher emits prose PLUS a `claims[]` array (`{value, unit, sourcePath}`); the gatekeeper cross-checks both directions — every numeral in the prose must map to a claims entry, and every claim's `sourcePath` must resolve into the structured inputs. Substring presence alone no longer passes; wrong-context numbers fail the mapping (required test, Codex closure caveat: same value + same unit + wrong `sourcePath` must FAIL). (Fully templated prose rejected — it removes the LLM drafting value; the claims array delivers the same checkability.)** Entity validation runs on canonical IDs (per phase 2), not raw names. **3 LLM calls per pipeline run (Sentinel, Strategist, Dispatcher) + 2 reserve for retries** — inside free-tier RPM and the 5-min envelope. All drafts flow through existing approval + audit plumbing. Nothing sends, ever.
8. **UI rework — 4 tabs** (~1.5d) — Live Events / Exposure / Simulation / **Action Packet** (playbook + drafts + approvals merged). Demo: parameterized Gulf chokepoint closure (closure %, surcharge, duration), date-stamped narrative. **Any `FAILED_TO_FALLBACK` agent run renders a visible "degraded — no live AI" badge on the packet** (mode field exists end-to-end; taxonomy split per phase 4 — healthy deterministic components never trigger the badge).
9. **Eval suite — 6 scenarios** (~2d) — Hormuz chokepoint, tariff-deadline (**deadline date parameterized** — Aug 10 may move; the research calls it "deadline-driven chaos"), Red Sea diversion, hurricane single-source (replay-only), supplier bankruptcy (First Brands precedent), zero-exposure hallucination control. **Zero-exposure control fixed (R4-11): the legacy `Atlantis` fixture is replaced by a valid-country/valid-sector event that genuinely matches no supplier (true no-exposure under the ISO/enum design); a SEPARATE invalid-taxonomy case asserts the off-enum event lands in `OTHER_UNMAPPED` — two distinct failure modes, two distinct cases.** **Per-scenario source manifests (R4-12, narrowed): each scenario fixture ships a manifest — source URL, accessed date, extracted claim, confidence, and `do-not-encode` flags for volatile values (tariff rates, Hormuz status) — so fast-moving claims are traceable and excluded from hard-coded logic.** Graders deterministic where possible (event enum, supplier IDs, citation coverage, simulator math exact); one flash-model judge only for the no-unsupported-claims prose check. **Live-mode eval asserts effective mode `LIVE_AI` and fails on silent `FAILED_TO_FALLBACK`; 429s logged.** Wall-clock measured here.
10. **Polish & ship** (~0.5d→~1d) — recorded demo run, README final, junk-file cleanup, `verify:full` green, acceptance-gate pass. **Ship deliverable per claude-os PROJECT-CONSTRAINTS (owner 2026-06-12): README/docs gain a SPECIFIC "Expansion & adoption" section — boilerplate future-work fails the gate.** Adopter class (named): the procurement/supply-chain function at US mid-market manufacturers (50–499 employees). What that adopter requires before real use (each item task-convertible): ERP integration for PO/inventory truth (NetSuite/Epicor/Dynamics-class, the systems this segment actually runs); email handoff of approved drafts (Outlook/Gmail); SSO + per-user auth (trigger: >1 real user); SOC 2 Type I path if sold as SaaS; scheduled scans (the roadmap-gated "2am" capability — trigger: first user asking for monitoring). Expansion order with triggers: Tier-2 CSV onboarding tooling (trigger: first real upload lacking inventory columns) → scheduled scans → post-MVP scenario pathways (trucking/FMCSA, DRAM, ransomware, export-control) → multi-tenancy. Adoption path: pilot with one procurement team → process-owner sign-off → function-wide rollout. **Discoverability (ADR-0001, 2026-06-17): when RESILIX is offered to the adopter's enterprise agent platform, publish an Agentic Resource Discovery (ARD) `ai-catalog.json` + signed trust manifest so it can be discovered AND cryptographically verified before connect — concrete draft + reasoning in `docs/adr/0001-agentic-resource-discovery.md`. NOT built in the MVP (fixed-source / fixed-pipeline; anti-scope forbids dynamic discovery).**

_**Timeline, honest arithmetic (rev 3, post-Codex):** ~14.5 dev-days (phase 2 grew +1d for CSV ingestion + driver swap + atomic mutations + V2 schema; ~0.5d spread across phases 4/7/9 for mode split, claims array, fixture rework) + 50% planning-fallacy buffer ≈ **~22 dev-days ≈ 4.5 weeks full-time-equivalent, or 8–9 calendar weeks at half-time.** Phase 9 (hand-computed fixtures for 6 scenarios) is the line most likely to consume the buffer._

## Key decisions & tradeoffs
- **Replay-first demo, live as verified toggle** — replay disclosed in-UI with capture dates; fallback runs badged; `verify:live` covers every prompt/schema pair.
- **Closed vocabulary + `OTHER_UNMAPPED` escape hatch** — the escape hatch, not the enum, is the real firewall (constrained decoding force-fits; it rarely fails to parse). Supplier names cross only as table-validated IDs.
- **Structural injection quarantine** — only Sentinel sees untrusted text; Dispatcher never does; gatekeeper blocks by enumerated checkable classes (numerals/URLs/entity names), not open-ended "factual" judgment.
- **$5 envelope with a real mechanism** — API-reported usage tokens × checked-in price table persisted per call in `decisionPacketAgentRuns` (replaces the salvage `length/4` estimate); **persisted fields per R4-10: input/output/total tokens, finish reason, retry/error class, pricing-table version, computed `costUsd`** — and `verify:live` is a real `package.json` script wired into `verify:full`, not a promise; per-agent fixture regeneration; Pro showcase ≤3 named passes; replay = $0.
- **3 LLM calls/run, not 5** — Verifier rationale is templated deterministically (trust component must not paraphrase itself wrong); the freed calls become retry reserve for Dispatcher's capped batch.
- **6 scenarios / 4 tabs / 2 live fetchers** (scope cut accepted round 1; owner confirms at sign-off). **Kept supplier bankruptcy over reviewer's cut** — owner's explicitly noted use case; now costs one *validated-ID* match rule (round-2 hardening). Dropped trucking (FMCSA keyed-feed dependency) — post-MVP.
- **Cross-model gate enforced in sequence** — only phase 1 (README text) may precede the true Codex round; build phases ≥2 are hard-gated on it (interim same-family reviews don't discharge the obligation). **Round 4 (true Codex, 2026-06-12) ran: 12 findings, all accepted (3 narrowed with logged reasons) — it caught code-level races, the neon-http/local-Postgres driver contradiction, the packet-contract mismatch, and the false zero-exposure control that three same-family rounds missed.**
- **Transactional integrity is now a plan invariant** — node-postgres driver, single-transaction approval (with the eventId reserved as a unique-constraint guard so one approval event can't commit two packet transitions), in-process single-run idempotency (single-instance MVP; cross-instance DB reservation is post-MVP); the "reuse LaunchOps plumbing" salvage claim is conditioned on these fixes.
- **Local PostgreSQL primary, in-memory fallback; Gemini best-under-$5; on-demand only; Next.js/TS monolith reusing LaunchOps approval/gatekeeper/audit** — unchanged from grill. **Stack rule (owner, 2026-06-12): every component must be widely-used AND free — Gemini is the only paid item.** Current stack already passes (Postgres/pg, Drizzle, Zod, papaparse, Vitest, Playwright, GDELT/NWS); the phase-2 driver swap removes the last hosted-service dependency (Neon). Future additions must clear both tests.
