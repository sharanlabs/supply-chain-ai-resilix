# Project Learnings (lessons.md)

> One line per mistake, never deleted. Review at session start. Same mistake twice = the system failed.

- P2.3 (2026-06-13, Codex [Med]): a read-compat/normalizer must only UPGRADE unambiguously-legacy payloads (keyed off a definite legacy signal, e.g. a missing version discriminant) — never "repair" a current/versioned payload. Silent repair of a malformed current packet masks a real bug; let the schema fail loudly. (First draft over-reached by backfilling modes regardless of version.)
- P2.4 (2026-06-13, Codex [High]): a "Zod<->DB alignment" test must build `typeof table.$inferSelect`-typed rows, NOT hand-written literals. A literal can satisfy the Zod schema while a real selected row cannot — default Drizzle `numeric()` infers `string`, `timestamp()` infers `Date`, and a nullable column yields `null` (which Zod `.optional()` rejects). Make it genuine: `numeric({mode:"number"})`, jsonb `.$type<...>()`, Zod `.nullish()` for nullable columns. (First draft asserted a falsehood that only passed on the literals.)
- P2.4 (2026-06-13, Codex [High], closure round): Drizzle pg `timestamp(col, {mode:"string"})` emits the Postgres text format `YYYY-MM-DD HH:mm:ss+HH`, which `z.string().datetime()` REJECTS — it is NOT ISO-8601. For an ISO string domain contract, keep the column Date-mode (house style) and convert with `Date.toISOString()` in the DB-row -> domain mapper. (The mode:"string" "fix" for the alignment lesson above was itself wrong; the second closure caught it.)
