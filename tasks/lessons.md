# Project Learnings (lessons.md)

> One line per mistake, never deleted. Review at session start. Same mistake twice = the system failed.

- P2.3 (2026-06-13, Codex [Med]): a read-compat/normalizer must only UPGRADE unambiguously-legacy payloads (keyed off a definite legacy signal, e.g. a missing version discriminant) — never "repair" a current/versioned payload. Silent repair of a malformed current packet masks a real bug; let the schema fail loudly. (First draft over-reached by backfilling modes regardless of version.)
- P2.4 (2026-06-13, Codex [High]): a "Zod<->DB alignment" test must build `typeof table.$inferSelect`-typed rows, NOT hand-written literals. A literal can satisfy the Zod schema while a real selected row cannot — default Drizzle `numeric()` infers `string`, `timestamp()` infers `Date`, and a nullable column yields `null` (which Zod `.optional()` rejects). Make it genuine: `numeric({mode:"number"})`, jsonb `.$type<...>()`, Zod `.nullish()` for nullable columns. (First draft asserted a falsehood that only passed on the literals.)
- P2.4 (2026-06-13, Codex [High], closure round): Drizzle pg `timestamp(col, {mode:"string"})` emits the Postgres text format `YYYY-MM-DD HH:mm:ss+HH`, which `z.string().datetime()` REJECTS — it is NOT ISO-8601. For an ISO string domain contract, keep the column Date-mode (house style) and convert with `Date.toISOString()` in the DB-row -> domain mapper. (The mode:"string" "fix" for the alignment lesson above was itself wrong; the second closure caught it.)
- P2.5 (2026-06-15, Codex+gate [High]): NEVER use the repo's 32-bit non-crypto `stableHash` (lib/utils.ts) as an identity / primary-key / dedup key — it is ~2^31 space (8 hex chars) and COLLIDES (Codex verified a concrete name+country pair → same `SUP-` id at the 2000-row cap), which silently merges two distinct records AND emits a false "duplicate, last-write-wins" audit line (poison in a trust/evidence product). It is fine ONLY for fingerprints where a collision is harmless (its existing agent-run uses). Content-derived IDs must use a collision-resistant digest (`createHash("sha256")…slice(0,16)`+). The risk is NEW when a hash first becomes a PK — flag any first-PK use of an existing hash helper.
- P2.5 (2026-06-15, acceptance-gate, 2 evidentiary BLOCKs): gate evidence must be CAPTURED TO DISK as a readable artifact, not just printed to the terminal — the read-only acceptance-gate (no Bash, by design) can only judge files. A live-pg PASS I ran but did not save read to the gate as "unproven"; and a STALE round-1 verify log left in /tmp made the gate cite wrong counts (94/6) vs the current state (100/5). Rule: tee verify/live-pg stdout to a named file each round, and delete superseded captures so the only on-disk evidence is authoritative.
- P2.6 (2026-06-15, Codex [High]): a composition/distribution test must pin the JOINT cells the design depends on, NOT just the marginals. Per-sector totals + per-country totals + cross-cut totals (Gulf count, ENERGY/CHEMICALS count) can ALL be preserved by a value-swap between two rows (Gulf ENERGY ↔ US LOGISTICS) that still guts the intended joint distribution (Gulf-origin energy/chem = the Hormuz exposure set). Derive the pinned (country × sector) cells from what each downstream scenario actually matches on. (First draft pinned marginals only — green but not a real guard.)
- P2.6 (2026-06-15, Codex [Med]): assert the REAL precondition, not a proxy. (a) A fail-loud completeness check on a DEDUPED collection must also assert the RAW pre-dedup count (totalRows) + zero-overwrites — a 151-row file with 1 duplicate dedups to 150 and slips a deduped-length-only check. (b) A command that doubles as a gated test (skip-if-env-missing) silently no-ops when misconfigured; an operational entrypoint (e.g. `seed:suppliers`) must FAIL LOUD on missing required config (DATABASE_URL), not inherit the test's skip.
- P2.7 (2026-06-17, Codex [Med]): a security ENABLE/REQUIRE flag parsed by a strict `=== "true"` is a FAIL-OPEN — an operator who writes `True` / `1` / `yes` / `" true "` *intending to secure the surface* is silently left AUTHLESS (the opposite of intent). Parse security booleans robustly (trim + lowercase; accept true/1/yes/on) through ONE shared helper, and test both the accepted and the rejected forms. (First draft used the strict equality.)
- P2.7 (2026-06-17, Codex [Low]): comparing two secrets of unknown/differing length with `timingSafeEqual` on raw buffers EARLY-RETURNS on a length mismatch → it leaks the configured secret's LENGTH (and a trivially-short configured secret silently passes). Hash BOTH sides to a fixed 32-byte SHA-256 digest BEFORE the constant-time compare (length-oblivious), and reject a weak/short configured secret as a 503 misconfig.
- P2.7 (2026-06-17, Codex [Low]): a predicate DUPLICATED across modules to dodge a heavy import (here: inlining `liveAiEnabled` to keep the AI-SDK out of the per-request auth path) is a latent DRIFT bug, not a clean fix — a drift-guard test only catches divergence after it ships. Extract a DEPENDENCY-FREE shared module both sides import (single source of truth); then drift is structurally impossible.
- P3.1 (2026-06-17, gate+Codex): a "never throws" resilience contract must guard EVERY external-facing call site, not just the obvious fetch — the injected clock (wrap in try/catch AND range-check: a FINITE `1e20` still throws in `new Date().toISOString()`), the URL build (a lone surrogate throws `encodeURIComponent`), and per-record mapping (one bad record must not abort the batch). The happy path hides these; the cross-model gate found them.
- P3.1 (2026-06-17, acceptance-gate [High]): DRY a SAFETY INVARIANT into ONE helper used by every call site. The "never serve cache past the stale bound" check lived in the failure path but not the spacing path — a 90-min-stale cache the failure path refused, the spacing path served 3s later. A duplicated invariant drifts; the MISSING TEST for the refusal branch is what let it ship (the gate's 2nd BLOCK reason). Pair the DRY helper with a test that hits the refusal branch.
- P3.1 (2026-06-17, Codex [Med]): treat UNKNOWN / IMPOSSIBLE / far-future inputs as the WORST case, never the default. A missing/malformed/2099 GDELT `seendate` returning `freshnessMinutes: 0` reads as "freshest", silently bypassing staleness warnings. Unknown/impossible/far-future → conservatively STALE; only a small clock skew → 0.
- P8 (2026-06-17, Codex closure + class-grep): a per-instance fix to a CLASS of bug leaves siblings. The date-TZ pin was applied to the `shortDate`/`shortTime` helpers, but TWO other date sinks (audit-trail `toLocaleString`, capture-date `toLocaleDateString`) still rendered un-pinned → a calendar-day SSR/client shift. Codex's closure caught one; a `grep "toLocale|new Date"` over the whole UI caught the other. When you fix a render/parse class, grep ALL sinks of that class and pin them together — never trust the named instance is the only one. (Same root as the claude-os "guard the boundary the data flows through, not the one you named".)
- P8 (2026-06-17, Codex [High]): an honesty/safety invariant must gate the ACTION, not just the DISPLAY. The gatekeeper verdict was correctly bound to the displayed badge (a static taste-read confirmed it), yet the Approve button still flipped state on a BLOCKED packet — visible but unenforced. Only the behavioral cross-model lens caught it. Gate the mutation on `approval.status==="PENDING" && gatekeeper.approvedForHumanReview`, and disable the control otherwise.
- P8 (2026-06-17, process): long-running background SUBAGENTS stream-idle-timed-out 3× this session (guidelines-monitor ×2, a fix frontend-specialist ×1) — infra, not logic. What worked: a dead subagent's edits still LAND in the working tree (assess the tree + finish/verify inline), and run critical verify/Codex/a11y as background BASH (stable) or inline rather than re-dispatching a hanging subagent. Treat a stream-timeout as infra failure, not data; don't retry blind.
- Governance (2026-06-17, Codex gate on PROCESS-CHARTER, 19/20 findings held): a "control" the maker can satisfy by self-report, or whose evidence writes only to `/tmp`, is NOT assurance. Independent controls produce COMMITTED evidence (`docs/claude/gates/<artifact>/`) recording maker+judge model+vendor+role; relabel self-report items (legibility/cost/recency/no-thrashing) honestly as operator-disciplines and automate where possible. maker != judge applies to governance docs too.
- Canon (2026-06-17, Codex): name the FULL standard, never a convenient subset - OWASP LLM Top-10 = all ten (each -> a control or an explicit N/A), + OWASP Agentic Top-10 2026 + ASVS/Web-Top-10/NIST-SSDF + NIST AI RMF. The deep tells - hollow comprehensiveness, false symmetry, narrating-the-obvious, voiceless prose, listing-not-deciding, defensive over-engineering - matter more than em-dashes; the done-test is "would a senior practitioner put their name on it". - Research scale (2026-06-17, Law 8): a 6-agent deep-research fan-out burned ~795K subagent tokens and hit the ACCOUNT session usage limit (resets 4pm ET), returning NOTHING - a total loss (0/7 domains). - P3.2 (2026-06-17, Codex [High]): every EXTERNAL source must cross ONE shared trust-boundary sanitizer, not a per-source copy. NWS alert text (id/areaDesc/headline/event + failure reasons) bypassed GDELT's control-char-strip + length caps because the sanitizer lived inside `gdelt.ts`. Extract it to a shared `sanitize.ts` (sanitizeText/isSafeHttpUrl) that GDELT AND NWS both import -> "a new source can't skip the boundary" becomes structural. Same root as the P2.7 "extract a dependency-free shared module" lesson, applied to the Law-11 trust boundary. - P3.2 (2026-06-17, Codex [Med] x2): the P3.1 "unknown/impossible/far-future -> worst-case-stale, never 0" rule RECURRED on a different source (NWS `sent`) AND a degraded primary must be VISIBLE. A malformed/far-future NWS `sent` returned freshnessMinutes 0 (falsely freshest); a GDELT FAILED outage returned an EMPTY list (invisible -> reads as "no disruptions = all calm"). Fix: apply the worst-case-stale guard to EVERY date sink (not just the one you named), and surface a down primary source as a schema-valid FAILED disclosure marker, never silent absence. Honest degradation = stale-not-fresh AND visible-not-absent.
- P3.2 (2026-06-17, Codex [Low]/[Partial]): a "drift guard" that recomputes the expected value through the SAME function + fixture + clock as the code under test is `f(x)===f(x)` -- it only catches "stopped using the function", not a content/logic change (both sides move together). Real teeth = an INDEPENDENT golden snapshot: pin the exact derived ids / contract values (here the 5 `sha256(url)[:16]` GDELT ids) so a fixture content swap or mapper regression fails. Keep the recompute as a cheap regression-lock, but never credit it as the drift detector.
- P3.2 (2026-06-17, Codex [Med]): a network-touching smoke (`verify:live`) must stay OUT of the deterministic `verify`/`verify:full` chain (flaky network would poison gate evidence + fail offline/CI) BUT must (a) be run once at the gate for evidence and (b) require a STABLE live anchor (NWS LIVE) so it can't pass green with ZERO working live sources. - G (2026-06-18, Codex REVISE — the cross-model gate VINDICATED, found 6 reals the same-family inline read rated PASS): a11y specs are unusually prone to FALSE GREEN, and an independent reviewer + per-node ground truth is the fix. - G (2026-06-18, npm overrides do not apply on an "up to date" lockfile): a scoped `overrides` (e.g. `vite>esbuild`) added to package.json is SILENTLY IGNORED by `npm install` when the lockfile already resolves (it reports "up to date", never writes the `overrides` field) — and even `rm -rf node_modules && npm install` reconciles to the EXISTING lock, so the override still doesn't take. Only `rm package-lock.json && npm install` (full regen) applies it — which re-resolves every caret range and can re-introduce just-cleared vulnerabilities. Lesson: a transitive dedup conflict (here a PRE-EXISTING `npm ls` ELSPROBLEMS: vite 8 wants esbuild ^0.27, npm deduped to drizzle-kit's 0.25.12) is fixed in a DEDICATED deps increment with a deliberate regen + re-gate, not a drive-by override; verify the real blast radius first (`npm ci` SUCCEEDED here, so CI was unaffected — ELSPROBLEMS is an `npm ls` validity warning, not an install failure). Don't ship a no-op override (it's slop).
