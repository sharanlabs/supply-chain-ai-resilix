## What changed (the coupled flip)
- **(2b)** `lib/pipeline/run-exception.ts`: `runExceptionPipeline` = `buildDecisionPacket`
  (pure V2 producer) + `saveDecisionPacket` + the existing idempotency mutex. Deleted
  the V1 body `executeExceptionPipeline`; dropped the LaunchOps engine imports. Returns
  the `DecisionPacket` UNION (fresh run = V2; the idempotency double-check can return a
  stored packet of either version).
- **(3)** `app/page.tsx`: async server component → `buildDecisionPacket({useLiveSignals:false})`
  (pure, NON-persisting, cached signals → no per-load save, no request-time network) →
  passes the real V2 to `components/launchops-dashboard.tsx` (new `packet` prop;
  `makeDemoPacket()` is the defensive fallback). Pipeline-failure path now logs
  server-side before falling back (was a silent swallow — fixed per the acceptance-gate).
- **Option A** — the V1 LaunchOps "Run live pipeline" panel + its e2e
  (`evals/e2e/launchops.spec.ts`) were RETIRED. Rationale: `ActionOpsPacketView` approves
  client-side/optimistic, while a run-produced packet IS persisted, so a "Run→Approve"
  UI would show APPROVED while the store stayed PENDING (a DB/UI provenance divergence).
  Run+approve intent is now covered by the default surface + the a11y approve test + the
  API-level evals.
- **(4)** Tests migrated to V2: new `evals/fixtures/decision-packet-v1.ts` (`makeV1Packet()`,
  the V1 oracle assembled via the retained LaunchOps engine) for the back-compat union +
  legacy-read tests; `pipeline.test` → V2 + persistence; `agent-mode` legacy-shim →
  `makeV1Packet()`; `decision-packet-version` → `makeV1Packet()`; `concurrency-integrity`
  spy → `buildDecisionPacket` (the new expensive boundary, direct import); `api-hardening`
  / `security-fail-closed` scenario id `SCN-LAUNCH-001`→`SCN-HORMUZ`. `n8n-callback` +
  the gated `db-*` tests are version-agnostic (unchanged). `evals/actionops-pipeline.test.ts`
  (added in sub-step 2a) asserts `runGraders(packet, gt).blocked === false` over the live
  V2 output.
- **Bundler fix surfaced by the cutover:** `lib/ingest/seed-suppliers.ts` `SEED_CSV_PATH`
  `fileURLToPath(new URL(..., import.meta.url))` → `path.join(process.cwd(), ...)`. The
  page cutover put this module in the `/` build graph; Turbopack rewrites `import.meta.url`
  to the chunk location and the bundled `URL` fails `fileURLToPath`'s cross-realm
  `instanceof` check → `next build` "collect page data for /" threw `ERR_INVALID_ARG_TYPE`.
- `app/api/run-exception/route.ts`: dropped `scenarioId`'s `.default("SCN-LAUNCH-001")`
  (retired id) so an omitted scenario flows to `DEFAULT_SCENARIO_ID` (SCN-HORMUZ).
